# Seed data — real machine locations

**Done.** 2.444 real machines are in the repo, imported from OpenStreetMap.
This doc now records where they came from, how to refresh them, and what the
earlier handover note got wrong.

## What shipped

- `tools/import_osm.py` — the importer. Python 3 standard library only, no pip
  install. Run `python3 tools/import_osm.py --refresh` to pull fresh data.
- `seed/machines.csv` — import through Supabase → Table editor → Import data
  from CSV. Easiest route from a phone or iPad.
- `seed/machines.sql` — the same rows as an upsert, for the SQL editor.
- The `SEED` block in `index.html` — regenerated by the same script, so local
  mode shows the real map instead of ten placeholder pins.

2.444 machines across 269 concelhos, including 80 in Madeira and the Azores.

## Where the data comes from

OpenStreetMap, queried through Overpass. The Portuguese OSM community mapped
the entire Volta network under `operator:wikidata=Q138952882` (SDR Portugal),
coordinated at <https://wiki.openstreetmap.org/wiki/Volta_PT>.

Licence is ODbL, which grants reuse explicitly. The map already credits
OpenStreetMap in the Leaflet attribution control, now worded to cover the
machine data as well as the tiles — keep it there.

### The earlier note was wrong about coverage

The previous version of this doc guessed OSM would be too sparse, and sketched
this query:

```
nwr(area.pt)["vending"="bottle_return"];
```

That returns **6** objects for the whole country, which is what made the path
look dead. The community did not use `vending=bottle_return`. Per their own
wiki page, Volta machines are tagged:

```
amenity=recycling
recycling_type=reverse_vending_machine
operator:wikidata=Q138952882
```

Querying `operator:wikidata` instead returns **2.445** — matching the ~2.500
the operator claims. The coverage was there the whole time under a different
tag. Worth remembering: check the local community's tagging page before
concluding a country is unmapped.

### RVMs only

Filtering on `recycling_type=reverse_vending_machine` does the job the old note
asked for. The network also has 8.000+ manual collection points at tills, and
"cheia" is meaningless for a person behind a counter. One element in the result
was a plain container and is dropped; everything else is a real machine.

Most rows still carry OSM's `fixme=survey the station…`, meaning a mapper
placed them from the operator's list but nobody has stood in front of them yet.
That is fine — confirming machines on the ground is exactly what VoltaCheck is
for.

## Concelho, not reverse geocoding

Every machine gets a `town` (its concelho), used by roadmap item 3.

The old note assumed Nominatim. It is not needed and their usage policy asks
people not to bulk reverse-geocode: 2.444 points at 1 req/sec is 40 minutes of
someone else's server. Instead the importer pulls the `admin_level=7` boundary
relations once (~33 MB) and does point-in-polygon locally — 2.443 of 2.444 land
exactly, in half a second, on one HTTP request. The odd one out sits just off
the Pico coastline in OSM and falls back to the nearest concelho.

## What we did *not* do

**Scraping volta.com.pt is off the table.** The site sits behind a bot
challenge — even `robots.txt` returns an interstitial rather than the file, so
their crawling rules cannot be read. That is a technical access restriction,
and per the repo's own rule we report it rather than work around it. We do not
need it anyway: OSM gives us the same coverage under a licence that says yes in
writing.

Asking SDR Portugal for an export is still worth one email, if only to get a
feed that stays fresh without waiting on OSM. It is no longer urgent.

## Refreshing

```
python3 tools/import_osm.py --refresh
```

Rewrites all three outputs. Then load `seed/machines.csv` (or `machines.sql`)
into Supabase and commit the changed `index.html`.

Re-running is safe by design:

- The SQL upserts on `external_id` (`osm:node/13722147127`), so a second run
  updates rows instead of doubling every machine.
- It only touches `source = 'osm'` rows. Machines people added through the app
  are `source = 'user'` and are never clobbered.
- Local mode rebuilds its list from `SEED` on every load and keeps reports in a
  separate map keyed by machine id, so a refreshed import reaches people who
  already have the app cached, without wiping what they reported.

Raw Overpass responses are cached in `tools/.cache/` (gitignored). Without
`--refresh` the script reuses them and hits nothing.

Note `overpass-api.de` was unreachable from the session that wrote this, so the
script walks a list of mirrors and falls through to `overpass.openstreetmap.fr`.
A full run takes about 40 seconds.

## Schema

`schema.sql` grew four columns, and is now safe to re-run over an existing
database:

- `external_id` — the source's id, unique. What makes re-imports idempotent.
- `town` — the concelho. Indexed on `lower(town)` for roadmap item 3.
- `source` — `'osm'` / `'sdr'` / `'user'`.
- `address` — nothing fills it. OSM carries no street address for these; the
  name ("Pingo Doce Altura") is the label people actually recognise, and the
  sheet now shows the concelho instead of raw coordinates.

Two fixes went in alongside:

- The `machines_insert` bounding box was mainland-only, so it would have
  rejected all 80 island machines anyone tried to add. It now covers Madeira
  and the Azores.
- Anonymous inserts are pinned to `source = 'user'` with a null `external_id`,
  so nobody on the public anon key can forge an imported row.

## A bug the real data exposed

`pull()` fetched machines with a single unpaged request. PostgREST caps how
many rows one request returns — 1000 by default on Supabase — so with 2.444
machines, live mode would have quietly shown about 40% of the country, and a
town search would have come up empty for whichever towns fell off the end.
Nothing would have errored; the map would just have been wrong.

It now pages through in blocks of 1000, for reports as well as machines — a
busy 72-hour window can pass 1000 reports just as easily. This was invisible
with ten placeholder machines and only became reachable once the real data
landed.

## One thing worth deciding

`index.html` went from 20 KB to 207 KB (6.7 KB → 58 KB gzipped) because the
2.444 machines are embedded for local mode. That is roughly Leaflet's own
weight and loads fine, but it is the price of keeping the app a single file
with no build step. If it ever feels heavy, the alternative is a separate
`machines.json` fetched at runtime — which is still no build step, but is no
longer one file.
